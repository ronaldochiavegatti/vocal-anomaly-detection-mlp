<objective>
Thread paraconsistent feature selection through `mode_train_ex()`'s fold/vowel loop for both Master and Expert networks (PARA-03), persist the selected indices via the existing `selected_save`/`selected_load` API, and collapse `predict_hierarchical_late_fusion()` with the validation loop's duplicated inline slicing block into a single function that is the sole consumer of those persisted indices for both discrete predictions and recorded probabilities (PARA-04).

Purpose: This is the actual integration this phase exists for — Plan 03-01's pure-math module has no effect on the pipeline until it is wired into the real training loop, and PARA-04's exact bug (discrete prediction vs. recorded probability silently diverging) can only be fixed by eliminating the second code path entirely, not by keeping both in sync by convention.
Output: `src/main.c` compiles cleanly; `mode_train()`'s default CLI path is behavior-preserving (verified structurally in this plan, verified by a real run in Plan 03-04); the new `ParaMode` toggle and `models/selected_*_fold*_v*.bin` persistence are ready for Plan 03-03's comparison-mode CLI entry.
</objective>
