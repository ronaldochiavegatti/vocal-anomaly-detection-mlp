Add `static void write_arch_compare_report(const ABResult results[4][3], const ArchConfig
arch_configs[4], const char *report_path)`. This function implements the EXACT decision
procedure below — deterministic, no judgment call, mirroring `write_smote_ab_report()`'s
fixed-rule precedent:

Step 1 (best regularization per architecture): for each architecture `a` in `0..3`, find
`best_reg[a]` = the `r` in `0..2` maximizing `results[a][r].macro_f1` (ties keep the
lower-index `r`, i.e. prefer `REG_LIGHT` over `REG_BASELINE` over `REG_STRONG` on an exact tie —
simplest deterministic tie-break, document it as such). Let `best_of[a] = &results[a][best_reg[a]]`.

Step 2 (best architecture overall): find `ao` in `0..3` maximizing `best_of[ao]->macro_f1`
(same lower-index tie-break rule).

Step 3 (1-SE band): compute `se = (best_of[ao]->ci[CI_MACRO_F1].upper -
best_of[ao]->ci[CI_MACRO_F1].lower) / (2.0f * 1.96f)` (bootstrap-CI-derived SE, per RESEARCH.md's
explicit recommendation — NOT the classic per-fold-array SE, since this codebase does not track
per-fold macro_f1 in an array; document this choice in the report text itself, verbatim: "SE
derivada do IC bootstrap (nao da formula classica CART por fold), por consistencia com a
infraestrutura estatistica ja estabelecida no projeto"). `band_lower = best_of[ao]->macro_f1 -
se;` (the band's upper bound is `best_of[ao]->macro_f1` itself, by definition).

Step 4 (McNemar gate): for each `a != ao`, compute `metrics_mcnemar(best_of[ao]->y_true,
best_of[ao]->y_pred, best_of[a]->y_pred, best_of[ao]->n, &chi2, &p)` (valid because all 12 arms
share the identical seed/fold/vowel ordering via `kfold_split()`'s internal reseed inside every
`mode_train_ex()` call, per RESEARCH.md Pattern 4 and Phase 1's established precedent). Record
`chi2`/`p` per architecture for the report table. `mcnemar_passes[a] = (p >= 0.05f)`.

Step 5 (adoption rule): a candidate architecture `a` PASSES iff `best_of[a]->macro_f1 >=
band_lower` AND (`a == ao` OR `mcnemar_passes[a]`). Among all passing candidates, `adopted =
argmin` of `(best_of[a]->param_count_master + best_of[a]->param_count_expert)` (ties keep the
lower-index `a`, i.e. prefer the simpler/earlier-labeled config on an exact parameter-count
tie). This guarantees `adopted == ao` whenever no simpler config passes both gates.

this codebase's existing convention — mirror `write_smote_ab_report()`'s structure): (1) a title
