<objective>
Thread `SmoteMode` through the training pipeline without changing the existing `train`/`full` CLI behavior, and add a single dedicated CLI mode (`smote-ab`) that runs the entire hierarchical-fusion training pipeline twice — once per SMOTE mode, under an identical seed/fold assignment — and produces a reproducible, code-computed A/B comparison report.

Purpose: This is the orchestration layer that makes SMOTE-04's "A/B report exists, adopt/reject decided reproducibly rather than by assumption" requirement possible with a single command, mirroring the `verify-rng` precedent Phase 0 established.
Output: `src/main.c` gains `ABResult`, `mode_train_ex()` (renamed/widened from `mode_train()`), a preserved `mode_train()` wrapper, `mode_smote_ab()`, `write_smote_ab_report()`, and one new `main()` dispatch line for `smote-ab`. No full pipeline run happens in this plan — that is plan 01-03's job.
</objective>
